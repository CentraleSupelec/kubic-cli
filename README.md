# Kubic CLI · Guide d'installation et d'utilisation

> Automatisez la création d'applications dans un Kubic, la configuration Vault, Argo CD & Kubernetes…

---

## 1. Prérequis

| Outil | Version conseillée | Rôle |
|-------|--------------------|------|
| Docker | ≥ 20.x | Exécution de l'image *kubic-cli* |
| Git    | ≥ 2.x  | Clone du repo & submodules |
| git-crypt (⚙︎)| ≥ 0.6 | Déchiffrement du dossier `secrets/` |

> Si vous ne gérez pas `secrets/` ou utilisez vos propres valeurs, **git-crypt** est le seul prérequis.

---

## 2. Installation 🐳

### 2.1 Cloner le dépôt

```bash
# Clone principal + submodules (optionnel mais recommandé tout de suite)
git clone git@github.com:ORG/kubic-cli.git && cd kubic-cli
git submodule update --init --recursive
```

### 2.2 Déverrouiller les secrets (git-crypt)

```bash
# Installez git-crypt si besoin (macOS)
brew install git-crypt
# Ubuntu / Debian
sudo apt-get install git-crypt

# Déverrouille le dossier `secrets/`
git-crypt unlock
```

> Pas de clé ? Récupérez la clé binaire fournie par un admin puis :
>
> ```bash
> git-crypt unlock path/to/your-key.key
> ```

### 2.3 Préparer le dossier `secrets/`

Le CLI lit automatiquement :

| Fichier | Rôle |
|---------|------|
| `.env` | Variables d'environnement (VAULT_ADDR, KUBE_API, …) |
| `config.toml` | Configuration applicative (ex : `gitops_path`) |
| `ca.crt` | Certificat racine du cluster Kubernetes |

```toml
# Exemple minimal de secrets/config.toml
yaml_header = "# Generated by kubic-cli\n"
gitops_path  = "shared-k8s-prd"
```

> Les fichiers étant montés en **lecture seule** dans le conteneur, aucun risque d'écrasement.

## 3. Premier lancement ⚡️

Le wrapper `kubic-cli` (fourni à la racine) se charge de tout :

1. Construit l'image Docker locale `kubic-cli:local` (une seule fois)
2. Monte vos secrets
3. Injecte automatiquement `--cluster-ca /run/secrets/ca.crt` si besoin

```bash
# Afficher l'aide
./kubic-cli --help

# Créer un projet complet
./kubic-cli create-project mysuperslug \
  --repo-url git@gitlab.com:ORG/helm-chart.git \
  --envs dev,prod

# Créer un projet avec les développeurs initiaux (Vault & Argo)
./kubic-cli create-project mysuperslug \
  --repo-url git@gitlab.com:ORG/helm-chart.git \
  --envs dev,prod \
  --devs alice,bob

# Générer tokens et kubeconfigs pour les développeurs existants
./kubic-cli setup-devs mysuperslug \
  --devs alice,bob \
  --cluster-ca secrets/ca.crt \
  --write-kubeconfig ./kubeconfigs/ \
  --duration 720h
```

> Toutes les variables présentes dans `secrets/.env` sont automatiquement exposées dans le conteneur.

> 💡 **Astuce : skipper certaines étapes**

* Vault : ajoutez `--skip-vault` (ou ne fournissez pas `--vault-addr/--vault-token`) pour sauter complètement la configuration Vault lors de `create-project`.
* Namespace Kubernetes : omettez `--api-server` ou `--api-token` pour sauter la création de namespace.

## 4. Commandes principales

| Commande | Description |
|----------|-------------|
| `create-project` | Crée un nouveau projet avec environnements et développeurs initiaux *(idempotent)* |
| `add-environment` | Ajoute des environnements à un projet existant *(idempotent)* |
| `add-dev` | Ajoute des développeurs à un projet existant *(idempotent)* |
| `setup-devs` | Génère tokens K8s et kubeconfigs pour développeurs existants |

Consultez `./kubic-cli <commande> --help` pour le détail de chaque commande.

### 4.1 Architecture et workflows

#### 📋 **Séparation des responsabilités**

Les commandes sont organisées en deux catégories :

**Commandes de création/modification** (écrivent dans GitOps + Vault) :
- `create-project` : Création initiale du projet
- `add-environment` : Ajout d'environnements
- `add-dev` : Ajout de développeurs

**Commande de génération** (readonly pour GitOps) :
- `setup-devs` : Génération des tokens et kubeconfigs

#### 🔄 **Workflows typiques**

```bash
# Workflow 1 : Création d'un nouveau projet
./kubic-cli create-project myapp \
  --repo-url git@gitlab.com:org/myapp.git \
  --envs dev,prod \
  --devs alice,bob
# → Commit/push → ArgoCD sync
./kubic-cli setup-devs myapp --devs alice,bob --cluster-ca secrets/ca.crt --write-kubeconfig ./

# Workflow 2 : Ajout d'environnements
./kubic-cli add-environment myapp --envs staging
# → Commit/push → ArgoCD sync
./kubic-cli setup-devs myapp --devs alice,bob --cluster-ca secrets/ca.crt --write-kubeconfig ./

# Workflow 3 : Ajout de développeurs
./kubic-cli add-dev myapp --devs charlie
# → Commit/push → ArgoCD sync
./kubic-cli setup-devs myapp --devs charlie --cluster-ca secrets/ca.crt --write-kubeconfig ./
```

#### ⚠️ **Important**

- **`setup-devs`** ne crée pas de nouveaux développeurs, utilisez `add-dev`
- La génération des mots de passe Argo CD est temporairement suspendue
- Les ServiceAccounts doivent être déployés (ArgoCD sync) avant `setup-devs`

## 5. Variables & configuration disponibles

### 5.1 Variables d'environnement (fichier `secrets/.env`)

| Variable | Description |
|----------|-------------|
| `VAULT_ADDR` | URL de Vault (https://vault.example.com) |
| `VAULT_TOKEN` | Token admin Vault |
| `KUBE_API` | URL du serveur API Kubernetes |
| `KUBE_API_TOKEN` | Token bearer pour l'API Kubernetes |
| `ARGOCD_URL` | URL du serveur Argo CD |
| `ARGOCD_USER` / `ARGOCD_PASS` | Login + mot de passe admin Argo CD |
| `ARGOCD_TOKEN` | Token bearer admin (alternative à USER/PASS) |
| `KUBIC_CLI_CONFIG` | (optionnel) Chemin d'un autre *config.toml* |
| `KUBIC_CLI_YAML_HEADER` | Préfixe inséré dans chaque YAML généré |
| `KUBIC_CLI_GITOPS_PATH` | Chemin par défaut du dépôt GitOps |
| `KUBIC_CLI_PWPUSH_URL` | URL custom de Password Pusher `/p.json` |

### 5.2 Clés disponibles dans `secrets/config.toml`

| Clé TOML | Default | Rôle |
|----------|---------|------|
| `yaml_header` | `"# Generated by kubic-cli\n"` | Texte ajouté en tête de vos YAML |
| `gitops_path` | `"shared-k8s-prd"` | Dossier contenant le dépôt GitOps |
| `pw_push_url` | `"https://pwpush.com/p.json"` | Instance *Password Pusher* à utiliser |

> Ces clés peuvent être surchargées par les variables d'environnement préfixées `KUBIC_CLI_` listées ci-dessus.

## 6. Mise à jour du dépôt (submodule)

Si le dépôt contient l'arborescence GitOps en tant que **submodule** (ex :`shared-k8s-prd/`), pensez à le récupérer et à le suivre :

```bash
# Initialiser puis mettre à jour à tout moment
git submodule update --init --recursive
# Pour tirer les dernières modifications
git submodule update --remote shared-k8s-prd
```

---

## 7. Récapitulatif « tout-en-un » 📝

```bash
# 1. Clone + submodules
git clone <repo> && cd kubic-cli && git submodule update --init --recursive

# 2. Déverrouiller les secrets (si git-crypt)
git-crypt unlock   # ou git-crypt unlock keyfile

# 3. Lancer le CLI
./kubic-cli --help  # construit l'image automatiquement
```

Enjoy ! 😊
